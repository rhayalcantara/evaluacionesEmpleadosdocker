## Reglas por método

**getCatalogos()**
- `forkJoin` de `empleadosController.Gets()` y `periodosController.Gets()`; construye los dos Map
  a partir de `data` (si `data` viene null/undefined → Map vacío).
- Si CUALQUIERA de las dos peticiones falla, esa parte cae a un Map vacío (usa `catchError` por
  petición, registra con `logger.warn`) y el observable **NO** emite error.
- Se cachea con `shareReplay(1)`: dos llamadas seguidas a `getCatalogos()` provocan **UNA sola**
  llamada a `empleadosController.Gets()` y una a `periodosController.Gets()`.
  `limpiarCacheCatalogos()` descarta la caché.

**getHistorialPorEmpleado(sec)**
- `forkJoin` de `evaluacionController.GetEvaluacionesPorEmpleado(sec)` y `getCatalogos()`.
- Cada evaluación → `mapearResumen(ev, empleados.get(ev.empleadoSecuencial) ?? ev.empleado ?? null, periodos.get(ev.periodId) ?? null)`.
- Devuelve `ordenarPorFechaDesc(resumenes)`.
- Ya NO llama a `empleadosController.Get(id)` (se elimina esa dependencia).

**getHistorialSubordinados(supervisorSec, fechaConsulta = hoy 'yyyy-MM-dd')**
- `empleadosController.Getsub(String(supervisorSec), fechaConsulta)`; si `data` está vacío/null → `of([])`.
- Para cada subordinado, `evaluacionController.GetEvaluacionesPorEmpleado(sub.secuencial)`; mapea
  cada evaluación con **el objeto subordinado** como empleado (tiene nombre, cédula, etc.) y el
  periodo del catálogo. Combina todo con `forkJoin` y devuelve `ordenarPorFechaDesc`.
- Pide los catálogos UNA vez (no una por subordinado).

**getHistorialConFiltros(filtros)**
- `forkJoin` de `datos.getdatos<ModelResponse>(this.datos.URL + '/api/Evaluacions')` y `getCatalogos()`.
- Filtra sobre las evaluaciones crudas:
  - `filtros.empleadoSecuencial` (si es número > 0) → `ev.empleadoSecuencial === valor`.
  - `filtros.periodoId` (si es número > 0) → `ev.periodId === valor`.
  - `filtros.estadoEvaluacion` (si no está vacío) → `coincideEstado(ev.estadoevaluacion, filtros.estadoEvaluacion)`
    (así `'SIN_INICIAR'` encuentra las que tienen estado `null`).
  - `filtros.fechaDesde` → `new Date(ev.fechaRepuestas) >= new Date(fechaDesde)`;
    `filtros.fechaHasta` → `<=`. Evaluaciones con `fechaRepuestas` null/inválida quedan EXCLUIDAS
    cuando hay filtro de fecha.
- Mapea con catálogos (igual que arriba) y devuelve `ordenarPorFechaDesc`.

**compararEvaluaciones(id1, id2)**
- `forkJoin` de `evaluacionController.Get(String(id1))`, `evaluacionController.Get(String(id2))` y `getCatalogos()`.
- Mapea ambas con catálogos y devuelve `compararResumenes(r1, r2)`.
- Si `compararResumenes` lanza (medio año o misma evaluación), el observable **emite error** con
  ese mismo `Error` (usa `throwError(() => e)` o deja que `map` propague la excepción). El
  `error.message` que ve el suscriptor debe ser el `motivo` de `puedeComparar`.

**getEstadisticasEmpleado(sec)** → `getHistorialPorEmpleado(sec).pipe(map(h => calcularEstadisticas(h)))`.
Con historial vacío el error `'No hay evaluaciones para este empleado'` llega como error del observable.

**getDatosEvolucion(sec)** → `getHistorialPorEmpleado(sec).pipe(map(h => datosEvolucion(h)))`.

**exportarHistorialAExcel(historial)** → `filasExcel(historial)` (síncrono).

## Criterios de aceptación
1. Compila; no quedan referencias a `empleadosController.Get(`; no hay lógica duplicada de
   `historial-utils` (mapeo, promedios, comparación, filas Excel se delegan).
2. Nombre, identificación, usuario, departamento y periodo se resuelven en las TRES rutas de carga.
3. Catálogos: una sola petición por servicio gracias a `shareReplay(1)`; fallo de un catálogo no
   rompe el historial.
4. Filtro de estado `'SIN_INICIAR'` devuelve evaluaciones con estado `null`.
5. Comparar con una de medio año → error observable con el motivo exacto de `puedeComparar`.
6. Estadísticas de un empleado con una final (total 93) y una de medio año (total 40) →
   `promedioGeneral = 93`, `evaluacionesMedioAno = 1`.
7. Sin `console.log`; usa `LoggerService`.
