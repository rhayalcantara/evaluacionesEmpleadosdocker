## Qué es
Un componente **standalone de solo lectura** que se incrusta en la fila de cada competencia del formulario
de evaluación (medio año y final) y en el historial. Muestra cuántos eventos de la bitácora del periodo
evidencian esa competencia ("2 logros · 1 incumplimiento") y, al desplegar, la lista de esos eventos.
**No modifica nada**: es evidencia para el supervisor, no puntuación.

## Contrato

```ts
@Component({ selector: 'app-bitacora-resumen', templateUrl: './bitacora-resumen.component.html',
  standalone: true, imports: [CommonModule], styles: [`…`] })
export class BitacoraResumenComponent implements OnChanges {
  @Input() empleadoSecuencial: number = 0;
  @Input() periodoId: number = 0;
  /** Id de la competencia (Objetivo.Id) de la fila donde se incrusta; puede ser de otro periodo que el evento. */
  @Input() objetivoId: number | null = null;
  /** Alternativa cuando no se conoce el id: nombre de la competencia; se empareja por normalizarTexto. */
  @Input() nombreCompetencia: string | null = null;
  /** 'compacto' (por defecto): solo el texto + botón desplegar. 'lista': siempre desplegado. */
  @Input() modo: 'compacto' | 'lista' = 'compacto';

  fila: IBitacoraResumenCompetencia | null;   // la fila del resumen que corresponde a esta competencia
  cargando: boolean; error: string; abierto: boolean;

  constructor(private bitacora: Bitacora) {}
  ngOnChanges(cambios: SimpleChanges): void;   // recarga solo si cambian empleadoSecuencial o periodoId (ambos > 0)
  get texto(): string;                          // textoResumen(fila) o 'Sin eventos' si fila es null
  get hayEventos(): boolean;                    // (fila?.total ?? 0) > 0
  alternar(): void;                             // abierto = !abierto (solo en modo compacto)
  fechaCorta(f): string; claseTipo(t): string; claseImpacto(i): string;   // delegan en utils
}
```

### Caché compartida entre instancias (obligatoria)
En una evaluación hay 12 filas de competencias → 12 instancias del componente para el mismo
`(empleadoSecuencial, periodoId)`. Solo debe hacerse **una** petición HTTP: mantén un
`private static cache = new Map<string, Observable<IBitacoraResumenCompetencia[]>>()` con clave
`` `${empleadoSecuencial}|${periodoId}` `` y el observable con `shareReplay(1)`. Expón
`static limpiarCache(): void`. Si la petición falla, elimina la clave de la caché para que el siguiente
intento vuelva a pedir.

### Emparejado de la fila
Con el array del resumen: si `objetivoId` está, primero `find(f => f.objetivoId === objetivoId)`; si no hay
coincidencia (o no hay `objetivoId`) y `nombreCompetencia` está, `find(f => normalizarTexto(f.nombre) ===
normalizarTexto(nombreCompetencia))`. Sin coincidencia → `fila = null` (texto 'Sin eventos').

## Reglas
- Sin `any`. Sin `console.*`. Sin `setTimeout`. Comentarios breves en español.
- Si `empleadoSecuencial <= 0` o `periodoId <= 0`: no pide nada, `fila = null`, sin error.
- El componente nunca lanza: los errores HTTP quedan en `error` con `mensajeError`.

## Criterios de aceptación (batería del orquestador con `Bitacora` simulado)
1. Dos instancias con los mismos inputs → `resumen` llamado **una** vez; `limpiarCache()` + nueva instancia → segunda llamada.
2. Con `objetivoId: 60` y resumen que contiene la fila 60 → `texto` correcto y `hayEventos` true.
3. Sin `objetivoId` pero `nombreCompetencia: 'Enfoque a Resultados'` y fila con nombre `'Enfoque a resultados'` → empareja.
4. Fila con total 0 o sin coincidencia → `texto === 'Sin eventos'`, `hayEventos` false, sin botón "Ver".
5. `alternar()` muestra la lista con un `<li>` por evento; en `modo: 'lista'` se muestra sin pulsar.
6. Error del API → `error` con el mensaje y el texto "Bitácora no disponible"; el siguiente `ngOnChanges` vuelve a llamar (la caché olvidó la clave).
7. Inputs en 0 → sin llamada HTTP.
