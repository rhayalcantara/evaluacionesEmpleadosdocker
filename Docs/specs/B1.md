## Qué es
Bitácora de Eventos de Desempeño: el supervisor registra hechos observables de un colaborador
(fecha del hecho, tipo, impacto, descripción y las competencias que evidencia). Es evidencia para la
evaluación; **no toca ninguna otra tabla**. Borrado lógico (`Activo = false`).

**Hechos del entorno que debes respetar**
1. `Empleados` es una **vista con filas duplicadas** por secuencial: usa siempre `FirstOrDefaultAsync` /
   `AnyAsync`, **nunca** `Single*`. Para nombres de varios empleados agrupa por `SECUENCIAL` y toma el primero.
2. El catálogo `Objetivo` (competencias) se **duplica por periodo** con Ids distintos. Un evento guarda
   el `ObjetivoId` con el que se registró; el endpoint `resumen` empareja por **nombre normalizado**.

## Función de normalización (privada, estática, en el controlador)
`static string Normalizar(string? s)`: `null` → `""`; quitar acentos (descomponer con
`Normalize(NormalizationForm.FormD)` y eliminar `UnicodeCategory.NonSpacingMark`), pasar a minúsculas,
colapsar espacios múltiples en uno, `Trim()`. Ej.: `"Flexibilidad y adaptación "` → `"flexibilidad y adaptacion"`.

## Rellenar campos de solo lectura (privado)
`async Task Completar(IEnumerable<BitacoraEvento> eventos)`: para cada evento y cada competencia,
`Nombre = Objetivo.nombre` y `Grupo = GrupoCompetencia.nombre` (una sola consulta a `Objetivo`
`Include(GrupoCompetencia)` con los ids implicados; si el objetivo ya no existe, `Nombre = "(competencia
eliminada)"`, `Grupo = ""`). El nombre del autor se devuelve en la propiedad **`registradoPorNombre`**:
como `BitacoraEvento` no la tiene, devuelve los eventos envueltos en un DTO definido **dentro de este
archivo**:

```csharp
public class BitacoraEventoDto : BitacoraEvento   // hereda todo; añade el nombre del autor
{
    public string? RegistradoPorNombre { get; set; }
    public static BitacoraEventoDto De(BitacoraEvento e, string? autor) { /* copia campo a campo + Competencias */ }
}
```
Todos los endpoints que devuelven eventos devuelven `BitacoraEventoDto` (con `competencias`, `nombre`,
`grupo` y `registradoPorNombre` rellenos). Autor = `Empleados.FirstOrDefault(SECUENCIAL == RegistradoPorSecuencial)?.NOMBREUNIDO`.

## Validación común (privada) — devuelve `string? error` (null = válido)
`async Task<string?> Validar(BitacoraEvento e)` en este orden; el primer fallo gana y el texto se devuelve
como `BadRequest(new { mensaje = "<texto>" })` (HTTP 400):
1. `e == null` → `"Cuerpo vacío."`
2. Empleado: `!await _context.Empleados.AnyAsync(x => x.SECUENCIAL == e.EmpleadoSecuencial)` →
   `"El empleado indicado no existe."`
3. Autor: `e.RegistradoPorSecuencial <= 0` → `"Falta el secuencial de quien registra."`
4. Fecha: `e.FechaEvento.Date > DateTime.Today` → `"La fecha del evento no puede ser futura."`;
   `e.FechaEvento == default` → `"La fecha del evento es obligatoria."`
5. Tipo: `string.IsNullOrWhiteSpace(e.Tipo) || !BitacoraEvento.Tipos.Contains(e.Tipo)` (comparación **exacta**,
   sensible a mayúsculas) → `"Tipo de evento no válido (Logro, Incumplimiento, Iniciativa, Conducta)."`
6. Impacto: igual con `BitacoraEvento.Impactos` → `"Impacto no válido (Alto, Medio, Bajo)."`
7. Descripción: `d = (e.Descripcion ?? "").Trim()`; `d.Length < 30` → `"La descripción debe tener al menos 30 caracteres."`;
   `d.Length > 2000` → `"La descripción no puede superar 2000 caracteres."`. Guarda la descripción **recortada** (`Trim`).
8. Competencias: `e.Competencias == null || e.Competencias.Count == 0` → `"Indique al menos una competencia."`;
   ids repetidos (`GroupBy(ObjetivoId).Any(g => g.Count() > 1)`) → `"Hay competencias repetidas."`;
   algún `ObjetivoId` que no exista en `Objetivo` → `"Alguna competencia indicada no existe."`

## Endpoints (todos `async`)

### `GET api/BitacoraEventos?empleadoid=&desde=&hasta=&tipo=&objetivoid=`
- `empleadoid` (int) **obligatorio**: si falta o es `<= 0` → 400 `{ mensaje = "Falta empleadoid." }`.
- `desde`, `hasta` (`DateTime?`): filtran `FechaEvento >= desde.Date` y `FechaEvento <= hasta.Date`.
- `tipo` (string?): filtro exacto por `Tipo` (sin normalizar; un tipo raro devuelve lista vacía, nunca error).
- `objetivoid` (int?): solo eventos que tengan esa competencia (`Competencias.Any(c => c.ObjetivoId == objetivoid)`).
- Siempre `Activo == true`. `Include(Competencias)`. Orden: `FechaEvento` desc, luego `Id` desc.
- 200 con `List<BitacoraEventoDto>` (puede ser `[]`).

### `GET api/BitacoraEventos/{id}`
- 404 si no existe **o** `Activo == false`. 200 con el DTO completo.

### `POST api/BitacoraEventos`
- Body `BitacoraEvento`. `Validar` → 400. Ignora `Id`, `FechaRegistro`, `FechaModificacion` y `Activo`
  que vengan en el body: `Id = 0`, `FechaRegistro = DateTime.Now`, `FechaModificacion = null`, `Activo = true`;
  cada competencia con `Id = 0` y `BitacoraEventoId = 0` (EF asigna). `FechaEvento = e.FechaEvento.Date`.
- Guarda, vuelve a leer con `Include(Competencias)`, `Completar`, y responde
  `CreatedAtAction(nameof(GetBitacoraEvento), new { id }, dto)` (HTTP **201**).

### `PUT api/BitacoraEventos/{id}`
- Body `BitacoraEvento`. Si `id != body.Id` → 400 `{ mensaje = "El id de la ruta no coincide con el del cuerpo." }`.
- Carga el existente con `Include(Competencias)`; si no existe o `Activo == false` → 404.
- Autoría: si `body.RegistradoPorSecuencial != existente.RegistradoPorSecuencial` → **403**
  `{ mensaje = "Solo quien registró el evento puede modificarlo." }` (comprobar **antes** de validar).
- `Validar(body)` → 400 (para la validación usa `body`, pero con `EmpleadoSecuencial` del existente).
- Actualiza SOLO: `FechaEvento (.Date)`, `Tipo`, `Impacto`, `Descripcion (Trim)`, `FechaModificacion = DateTime.Now`
  y **reemplaza** las competencias (elimina las filas actuales de `BitacoraEventoCompetencia` del evento y
  añade las nuevas con `Id = 0`). **No cambia** `EmpleadoSecuencial`, `RegistradoPorSecuencial`,
  `FechaRegistro` ni `Activo`. Responde **204**.

### `DELETE api/BitacoraEventos/{id}?secuencial=`
- `secuencial` (int) obligatorio; si falta o `<= 0` → 400 `{ mensaje = "Falta secuencial." }`.
- No existe o ya inactivo → 404. `secuencial != RegistradoPorSecuencial` → 403 (mismo mensaje de autoría).
- Borrado lógico: `Activo = false`, `FechaModificacion = DateTime.Now`. **No borra filas.** Responde 204.

### `GET api/BitacoraEventos/resumen?empleadoid=&periodoid=`
- Ambos obligatorios (`<= 0` o ausentes → 400 `{ mensaje = "Faltan empleadoid o periodoid." }`).
- Periodo: `periods.FindAsync(periodoid)`; no existe → 404.
- Competencias del periodo: `Objetivo.Include(GrupoCompetencia).Where(o => o.PeriodoId == periodoid)`
  ordenadas por `GrupoCompetenciaId`, `Id`. Si el periodo no tiene competencias → 200 `[]`.
- Eventos: activos del empleado con `FechaEvento` entre `FechaInicio.Date` y `FechaFin.Date` (inclusive),
  `Include(Competencias)`, `Completar`.
- Emparejar: un evento cuenta para la competencia `o` del periodo si alguna de sus competencias tiene
  `Normalizar(nombreDelObjetivoDelEvento) == Normalizar(o.nombre)` (busca el nombre del objetivo del
  evento en la tabla `Objetivo` por su `ObjetivoId`, aunque sea de otro periodo).
- Respuesta 200: lista de objetos anónimos, una fila por competencia del periodo:
  `{ objetivoId = o.Id, nombre = o.nombre, grupo = o.GrupoCompetencia?.nombre ?? "", logros, incumplimientos,
  iniciativas, conductas, total, eventos = List<BitacoraEventoDto> }` donde los contadores son conteos por
  `Tipo` de los eventos emparejados y `total` es su suma (= `eventos.Count`).

### `GET api/BitacoraEventos/equipo?supervisor=&desde=&hasta=`
- `supervisor` (int) obligatorio (→ 400 `{ mensaje = "Falta supervisor." }`); `desde`/`hasta` opcionales.
- Subordinados: `Empleados.Where(e => e.JEFEINMEDIATO_SECUENCIAL == supervisor)` **agrupados por
  `SECUENCIAL`** (vista con duplicados) → (secuencial, NOMBREUNIDO, CARGO) del primero de cada grupo.
- Eventos activos de esos secuenciales en el rango (si se dio).
- Respuesta 200: una fila **por subordinado** (aunque tenga 0 eventos), ordenadas por nombre:
  `{ empleadoSecuencial, nombre, cargo, total, logros, incumplimientos, iniciativas, conductas,
  ultimoEvento = (DateTime?) fecha máxima de FechaEvento o null }`.

## Reglas generales
- Todas las consultas con EF/LINQ parametrizado; nunca SQL concatenado.
- Ningún endpoint lanza excepción por datos raros: parámetros inválidos → 400 con `{ mensaje }`.
- Nada de `Console.WriteLine`. Comentarios breves en español.
- Una sola clase de controlador + la clase `BitacoraEventoDto` en el mismo archivo, `namespace EvaluacionEmpleadosApi.Controllers`.
- `using` necesarios: `System.Globalization`, `System.Text`, `Microsoft.EntityFrameworkCore`, `Microsoft.AspNetCore.Mvc`, `EvaluacionEmpleadosApi.Models`.

## Criterios de aceptación (los verifica el orquestador con HTTP real)
1. POST válido → 201 con `id > 0`, `fechaRegistro` de hoy, `fechaModificacion` null, competencias con `nombre` y `grupo`, `registradoPorNombre` no vacío.
2. POST con fecha de mañana, tipo `logro` (minúscula), impacto `Crítico`, descripción de 10 caracteres, sin competencias, competencia repetida, competencia 999999 o empleado 99999999 → 400 con el mensaje de la regla.
3. GET lista ordenada desc por fecha, solo activos; filtros por rango, tipo y objetivoid funcionan; sin `empleadoid` → 400.
4. PUT de otro autor → 403; PUT válido cambia tipo/impacto/descripción/competencias, sella `fechaModificacion`, conserva `fechaRegistro`, autor y empleado.
5. DELETE lógico: 204; después GET/{id} → 404 y no aparece en la lista; DELETE de otro autor → 403; sin `secuencial` → 400.
6. `resumen` excluye eventos fuera de las fechas del periodo e inactivos; `total = suma de tipos = eventos.Count`; periodo inexistente → 404; sin parámetros → 400.
7. `equipo` incluye a cada subordinado con conteos coherentes; sin `supervisor` → 400.
